# Changelog

and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Release sections are **generated by release-please** from Conventional Commit messages when a release PR is merged (`.github/workflows/release-please.yml`). Do not add an `[Unreleased]` section by hand: release-please inserts each new version above it, which duplicates every entry. Put the detail of a change in its commit body, and long-form explanations in `docs/`.

### Detailed release notes

Hand-written notes for the changes in this release (written before the changelog was generated by release-please).

#### Added
- **WooCommerce Product Schema (`Atlas\Schema`):** Added native `Product` and `Offer` structured data (price, currency, availability, description, image, and optional `AggregateRating`), supporting `wc_get_product()` with post meta fallback, filterable via `atlas_schema_product`.
- **Advanced Markdown Engine (`Atlas\Markdown_Endpoint`):** Added GitHub-flavored Markdown table conversion (`core/table`), language-tag preservation in code fences (`core/code`), and standard divider conversion (`core/separator`). Expanded unit test suite to 235 passing tests.
- **Security & Headers (CSP Production Auto-Enforce, HSTS Preload Safety):** `Atlas\Security_Headers` now features environment-aware CSP auto-detection: production environments (`wp_get_environment_type() === 'production'` without `WP_DEBUG`) automatically enforce CSP policies (`MODE_ENFORCE`), while local development and staging default safely to `MODE_REPORT_ONLY`. Added HSTS `includeSubDomains` and `preload` operator documentation with browser-commitment safety warnings.
- **Performance & Cache-Busting (`interactivity.css` Content Hash):** `Atlas\Assets` enqueues `src/css/interactivity.css` using an MD5 content-hash version string, ensuring immediate browser/CDN cache invalidation upon any CSS edit without requiring a manual theme version bump. Unit test suite expanded to 231 passing tests.
- **SEO & Social Optimization (OG Dimensions, og:locale, rel="prev/next"):** Added `og:image:width` and `og:image:height` metadata extraction from attachment IDs (filterable via `atlas_seo_og_image_dims`), automatic `og:locale` from WordPress locale, and `rel="prev"` / `rel="next"` archive pagination links (`print_pagination_links()`) respecting permalinks and backing off cleanly when an SEO plugin is present.
- **AI & GEO Expansion (LLMs.txt Blog Posts & Metadata, AI Crawlers):** `/llms.txt` now includes a `## Posts` section for published blog posts (capped at 20 via `MAX_POST_ENTRIES`, filterable via `atlas_llms_txt_include_posts`), `/llms-full.txt` embeds YAML-style metadata blocks (Date, Author, URL) for improved AI ingestion, and `Atlas\Robots` expands default AI crawler support to include `Applebot-Extended`, `Bytespider`, `Amazonbot`, `FacebookBot`, and `Bingbot`.
- **Schema & Performance Enhancements (wordCount, Speakable, Archive Cache, Tag Processor):** `Atlas\Schema` adds `wordCount` (with multibyte fallback) and Google `SpeakableSpecification` (`article`, `h1`, `.entry-summary`) to `BlogPosting` nodes, and implements independent transient caching for category, tag, taxonomy and post-type archives (`term_{id}`, `archive_{type}`). `Atlas\Infinite_Scroll` migrates next-page link parsing to `WP_HTML_Tag_Processor` with regex fallback for robust HTML handling. Total test suite expanded to 230 unit tests (all passing).
- **Typography, Side Padding and Compact Language Switcher:** New `docs/02-frontend-and-styles/07-typography-and-layout.md` and `tests/test-typography.php` (+20 PHP tests, total 224; mutation-checked). Smaller font scale (body 14-15 px, h1 26-34 px). Root left/right padding `clamp(1rem, 4vw, 2rem)`, also used by the header and footers so everything lines up (verified 360-1920 px, no horizontal scroll). The language switcher shows `EN / HI`, with `aria-label="HI (हिन्दी)"` (contains the visible text, WCAG 2.5.3) and the native name as tooltip. Contact fields stay at 16 px (iOS Safari zoom). The E2E harnesses now take font sizes from the real `theme.json` and the six visual baselines were refreshed deliberately.
- **Schema Article and Breadcrumb Tests (+18, total 204):** New `tests/test-schema-nodes.php` covers the `BlogPosting` node (fields, featured image, author `sameAs` only when supplied, empty-title fail-closed, hostile titles round-trip without breaking the script) and `BreadcrumbList` for categorised and uncategorised posts, category archives, post-type archives and the front page, plus the cache and its hook wiring. Test doubles gained `WP_Post`, `WP_Term`, `WP_Post_Type`, an options store and the template tags the graph reads; mutation-checked (6 mutations). Verified on a live site. Docs: `03-json-ld-schema.md` §6, `03-testing-strategy.md` §7.
- **Icon System (`Atlas\Icons`) and Icon-First Controls:** Replaced Unicode glyph stand-ins (hamburger, X, sun, moon, clipboard) with an inline-SVG registry (10 original icons; `stroke=currentColor`, decorative, sized before CSS loads, no request or JS). Icon-only controls: menu toggle, in-panel close (was the text "Close menu"), theme toggle, and the copy button (was an icon plus the words "Copy quote"/"Copied!"; now icon only, copy -> check, announced once through a live region). Icon + label where the word matters: Retry, Sign in again, Load more posts, Send message. Language switcher, skip link and pattern CTAs stay text on purpose. Every icon-only control has an `aria-label`, a matching `title` (the theme toggle's is state-bound) and a 44px target (copy: 32px, 44px on coarse pointers). New `docs/02-frontend-and-styles/06-icons.md`, `tests/test-icons.php` (+15 PHP tests, total 186; mutation-checked) and `tests/e2e/icons.spec.js`. Verified on the live site and by viewing light/dark/open-drawer screenshots.
- **Mobile Navigation: Zero Layout Shift and a No-JS Menu:** The drawer layout (collapsed `visibility:hidden` panel plus a visible toggle) is now pure CSS from the first paint instead of appearing only after hydration, and the toggle is a real link (`href="#atlas-nav-panel"`, `role="button"`) that opens the menu with **no JavaScript** through `:target`, with an in-panel "Close menu" link. `navigation.js` takes over once hydrated (`preventDefault`, Space key, adopts an already-open `#atlas-nav-panel`). The JS-only theme toggle now reserves its box while `[hidden]`. Measured on the live site: mobile CLS 0.12 -> 0.000, Lighthouse Performance 96 -> 100, header 61 px before and after hydration; the menu works with JS disabled and with the module blocked. `scripts/lighthouse.sh` now gates CLS at 0.1. New `tests/e2e/navigation-layout.spec.js` (layout, no-JS, blocked-module and keyboard guards) and `tests/test-fixtures.php` (harness-vs-header drift guard); 7 new PHP tests (total 171). Docs: `01-interactivity-api.md`, `04-accessibility.md` §3, `01-performance-budget.md` §6, `03-testing-strategy.md` §7.
- **Accessibility & Performance Tooling, With Real Fixes:** Added axe-core (`@axe-core/playwright` 4.14.0, dev-only) E2E scans of the fixtures in light and dark mode on desktop and mobile (`tests/e2e/accessibility.spec.js`, configurable against a live site via `A11Y_BASE_URL`), a fast PHP colour guard (`tests/test-colors.php`: every referenced preset exists, AA pairs hold in both modes), and `scripts/lighthouse.sh` (pinned Lighthouse 13.6.0 gate). The E2E fixtures now take colours from the real `theme.json` (`/theme-palette.css`) and read server-seeded Interactivity state, instead of hand-copied values that had drifted. Visual baselines refreshed. 18 new PHP tests (total 164). Measured on the live site: Performance 74 -> 96, Best Practices 96 -> 100, SEO 92 -> 100, TBT 950 ms -> ~0. Docs: `04-accessibility.md` §2/§9, `03-dark-light-mode.md` §5, `01-performance-budget.md` §5-6, `03-testing-strategy.md` §7.
- **`<meta name="description">`:** `Atlas\Seo` now prints the standard description tag (same cleaned, capped text as `og:description`; nothing when empty). Lighthouse SEO 92 -> 100.
- **Contact Submissions: Private Storage, Retention & GDPR Tooling (`Atlas\Submissions`):** Accepted submissions are stored in a private `atlas_submission` post type (not public/queryable/searchable/REST; all capabilities require `manage_options`), so a failed `wp_mail()` no longer loses the message (`mail_failed` status). A daily cron purges entries after 90 days (`atlas_submission_retention_days`, floor 1 day, batched), core Export/Erase Personal Data tools find and remove a person's submissions by email, and suggested privacy-policy text is registered. Opt out with `atlas_contact_store_submissions`. `Contact_Form` now fires `atlas_contact_form_submitted` and exposes `atlas_contact_form_verify_challenge` as a vendor-neutral CAPTCHA/Turnstile extension point (default pass). 21 new tests (total 146), mutation-checked, and verified end to end on a live site (submit, store, export, erase, cron). Docs: `03-data-protection.md` §7, `05-forms-and-validation.md` §5, `02-end-user-guide.md` §6, `03-testing-strategy.md` §7.
- **SEO & Schema Output Tests (+19, total 125) and JSON-LD Hardening:** New `tests/test-seo-schema.php` covers noindex (search, maintenance), OG/Twitter escaping against hostile titles, canonical, description cap, hreflang, gate filters, JSON-LD graph/caching/invalidation and SEO-plugin back-off. The smoke test now also checks for a single canonical link and valid, `<`-free JSON-LD on the live home page. Test doubles for conditional tags and `esc_url` now mirror core. Docs: `03-json-ld-schema.md` §5, `03-testing-strategy.md` §7.
- **Release Packaging & Live Smoke Test:** Added `scripts/build-release.sh` (version-sync check across `style.css`/`functions.php`/`package.json`, build, clean deterministic `atlas-theme-<version>.zip` + SHA-256, content verification), a `package` CI job that proves it on every PR, and a release-time job that attaches the zip to the GitHub Release. release-please now also bumps `style.css` and `functions.php` (`extra-files` + version markers). Added `scripts/smoke-test.sh` that verifies headers, the contact token endpoint and token rejection against a running site. Docs: `06-automation-setup.md` §4/§6, `03-testing-strategy.md` §7, `05-updates-and-recovery.md`.
- **Markdown Endpoint & Assets Test Coverage:** 16 new unit tests for `Atlas\Markdown_Endpoint` (conversion, hostile `javascript:` and `<script>` input, caching, size cap) and `Atlas\Assets` (copy controls, theme-mode script, CSP nonce). Total suite: 106 tests. The `esc_url_raw` test double now rejects non-allow-listed protocols like core.
- **Markdown Endpoint Caching & Size Cap:** `?format=md` output is cached in a transient keyed by post ID, modified time and locale (1 h), and capped at 512 KB on a UTF-8 boundary (`atlas_markdown_max_bytes`), so crawl bursts no longer re-run block renderers. Docs: `02-markdown-endpoints.md`, `04-rate-limiting-and-abuse.md` §5.
- **CI Supply-Chain Hardening & Dependency Auditing:** Pinned every GitHub Action to a full commit SHA, added top-level least-privilege `permissions: contents: read` and branch-safe `concurrency`, added an `audit` job (`composer audit --locked`; blocking `npm audit` for shipped deps and at `critical`; informational at `high`), and added `.github/dependabot.yml` (weekly grouped PRs for Actions, npm and Composer). Shipped (production) dependencies currently audit at 0 vulnerabilities; the remaining advisories are build-tool-only. Docs: `06-automation-setup.md` §2/§4, `02-testing-and-ci.md` §4.
- **Contact Form Hardening (`Atlas\Contact_Form`):** Replaced the anonymous `wp_rest` nonce (which froze into cached HTML and gave no real CSRF protection) with a stateless HMAC-signed form token (`issue_token()` / `verify_token()`, 12 h TTL via `atlas_contact_token_ttl`) whose signed age also powers the timing check, so a bot can no longer forge or back-date it. The rate limiter now fails closed for an empty/invalid IP (shared `unknown` bucket), uses keyed-HMAC counter keys instead of `md5(ip)`, and increments atomically via `wp_cache_incr` on a persistent object cache (transient fallback). Mail subject and `Reply-To` use `Contact_Form::header_safe()` to block header injection and display-name spoofing. 16 new unit tests (total 88). Docs: `05-forms-and-validation.md` §4-5, `04-rate-limiting-and-abuse.md` §3, `04-hosting-agnostic-security-and-zero-trust.md` §3, `04-caching-and-scaling.md`.

#### Fixed
- **CI Visual Regression Always Failing (tests):** the baselines were rendered on macOS with Google Chrome and a system font stack, while CI renders on Linux with bundled Chromium, where that stack falls back to different fonts; element heights differed (for example 1046 vs 988 px), so the six visual tests failed on every CI run since they were added. The fixtures now load the theme's real Inter/Sora webfonts and heading typography from `theme.json`, each visual test waits for and asserts the fonts are loaded, and baselines are per OS (`-darwin` / `-linux`). The Linux set is produced by the new manual **Update visual baselines (Linux)** workflow. Loading real webfonts exposed a timing dependency in the hydration layout-shift test (fonts arriving after first paint on the slower CI runner reflowed text, CLS 0.009-0.016, unrelated to hydration); the test now holds the theme modules until the fonts are loaded and measures only what hydration moves. It still catches both known regressions (theme toggle revealed with `display:none`; drawer layout gated on hydration).
- **Theme Font Scale Was Silently Ignored (typography):** WordPress discards theme font-size presets that reuse a core slug unless `defaultFontSizes` is `false`, so `small`, `medium`, `large` and `x-large` never applied and body text was 20 px on desktop (core's 13/20/36/42 px). `defaultFontSizes: false` is now set and guarded by a test. (`defaultSpacingSizes` has the same issue; left as a documented design decision, see `07-typography-and-layout.md` §5.)
- **No Side Padding:** `useRootPaddingAwareAlignments` was on without any root padding, so content touched the screen edge on phones.
- **Notifications Part Duplicated and Misplacing Layout:** it was included in both header and footer, duplicating ids (`atlas-session-modal-title/-desc`) and live regions, and as an empty first flex child it pushed the site title right and centred the footer copyright. It now exists once, in the header, before the flex group.
- **Flaky Mobile Drawer Test:** `navigation.spec.js` pressed the header toggle while the open panel covered it (impossible for a user; it only passed during the 0.3 s slide-in), failing about 4% of runs under load (5 of 120). It now closes with the in-panel close control. 200/200 afterwards.
- **Stale Structured Data After Site-Wide Changes (SEO):** `Atlas\Schema::flush_cache()` only deleted the front-page graph, and nothing invalidated the other cached graphs when the site title, logo, an author's display name or a category changed, so every post's JSON-LD (publisher, author, breadcrumb) stayed stale for up to 12 hours. Cache keys now carry a generation (`atlas_schema_cache_gen`); `flush_cache()` bumps it, invalidating every graph at once, and runs on theme switch, `blogname`, `home`/`siteurl`, theme mods (logo), profile update and term edit/delete. Verified live: renaming the site changes the publisher in an already-cached post on the next request. Docs: `03-json-ld-schema.md` §6, `04-caching-and-scaling.md`.
- **Dark-Mode Link Colour Leaked Onto Controls:** The earlier dark-mode link fix overrode every `<a>` with a selector, so the nav toggle and the language switcher (which set `color: inherit`) turned blue. Links are now coloured by a dark-mode aware `link` preset (`theme.json` link element -> `var:preset|color|link`; `#2563eb` light, `#60a5fa` dark) and the selector override is gone. The E2E fixture server now emits the link element style from the real `theme.json`, so fixtures show real link colours.
- **Cumulative Layout Shift on Mobile (performance):** Before hydration the primary nav rendered inline and wrapped (header 86 px); after `navigation.js` ran it collapsed to the drawer (58 px), shifting the page up 28 px (CLS 0.12). The closed drawer layout no longer depends on hydration. See "Mobile Navigation" under Added.
- **Dark-Mode Contrast Failures (accessibility):** (1) Cards in `quotes-masonry`, `testimonial` and `impact-metrics` used the fixed `white` background with `dark` text, which is `#f8fafc` in dark mode, so text was 1.04:1 on white. They now use a new `surface` preset (white in light mode, `#1e293b` in dark; 13.98:1). (2) Metric numbers in `impact-metrics` used the brand `accent` as text (2.68:1 on the light surface); they now use a new text-safe `accent-text` preset (4.95:1 light, 6.37:1 dark). (3) Links used `primary` on the dark surface (3.45:1); in dark mode they are now `#60a5fa` (7.02:1). Brand colours and buttons are unchanged.
- **Late Heading-Font Swap & Emoji Overhead (performance):** The Sora heading font is now preloaded alongside Inter (it was the Lighthouse layout-shift culprit), and core's front-end emoji detection script is removed (`atlas_keep_emoji_scripts` restores it); it caused a ~1.2 s long task and the only CSP issue Chrome logged.
- **JSON-LD Script Breakout (security):** `Atlas\Schema` only neutralised `</`, so a title or site name containing `<!--<script>` could push the HTML parser into the "script data double escaped" state and swallow the real closing tag and the rest of the page. The graph is now encoded with `JSON_HEX_TAG | JSON_HEX_AMP` (`<`, `>`, `&` become `\u003C`, `\u003E`, `\u0026`). Regression test added.
- **Maintenance Page Rendered as Raw Block Markup:** `Atlas\Maintenance::override_template()` returned the path of `templates/maintenance.html`, which PHP included raw (unrendered block comments, no `<html>`, head or CSS). It now resolves the block template (child theme first, `blank` as fallback) and hands it to core's `template-canvas.php`, producing a full themed 503 document. Verified on a live site (503, `Retry-After`, `noindex` intact). Tests updated (total 90). Docs: `05-coming-soon.md` §3.
- **Desktop Navigation Drawer Toggle Bug:** Fixed `.atlas-nav__toggle` base style from `display: inline-flex` to `display: none` in `theme/src/css/interactivity.css`. Prevented the mobile hamburger/sandwich toggle button from showing unconditionally on desktop viewports above the 48rem breakpoint upon client-side hydration.
- **503 Maintenance Mode Cache Poisoning Prevention:** Issued `nocache_headers()` and wrapped header emission with `headers_sent()` checks in `Atlas\Maintenance::maybe_intercept()` to prevent CDNs, reverse proxies, and browser caches from retaining 503 error responses after maintenance mode concludes.
