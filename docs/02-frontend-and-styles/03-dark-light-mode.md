# 03. Flicker-Free Dark/Light Mode Engine

**File:** `docs/02-frontend-and-styles/03-dark-light-mode.md`  
**Module:** Frontend & Styles  

## 1. The Challenge: Flash of Unstyled Content (FOUC)
Implementing Dark Mode often results in FOUC—a jarring visual flash where the site briefly loads in light mode before the JavaScript kicks in and switches it to dark mode. 

To provide an enterprise-grade user experience, this theme implements a **Flicker-Free runtime evaluation** strategy.

## 2. Core Architecture & CSS Strategy
Instead of writing separate CSS stylesheets for dark and light modes, the theme utilizes a `data-theme` attribute on the `<html>` element combined with CSS Custom Properties (generated by `theme.json`).

```css
/* Base (Light Mode) Variables mapped to theme.json presets */
:root {
    --brand-bg: var(--wp--preset--color--light);
    --brand-text: var(--wp--preset--color--dark);
}

/* Dark Mode Overrides */
:root[data-theme="dark"] {
    --brand-bg: var(--wp--preset--color--dark);
    --brand-text: var(--wp--preset--color--light);
}
```

## 3. The Runtime Blocking Script (Head Injection)
To prevent FOUC, a minuscule, highly optimized inline JavaScript snippet is injected directly into the `<head>` of the document (before any DOM rendering occurs). 

This script executes instantly, checking:
1. The user's saved preference in `localStorage`.
2. If no saved preference exists, the system/OS preference via `window.matchMedia('(prefers-color-scheme: dark)')`.

```html
<script>
  (function() {
    try {
      var localTheme = localStorage.getItem('nexus-theme-mode');
      var sysTheme = window.matchMedia('(prefers-color-scheme: dark)').matches;
      if (localTheme === 'dark' || (!localTheme && sysTheme)) {
        document.documentElement.setAttribute('data-theme', 'dark');
      } else {
        document.documentElement.setAttribute('data-theme', 'light');
      }
    } catch (e) {}
  })();
</script>
```

> **CSP Collision — Mandatory:** This inline script conflicts with the strict Content Security Policy defined in `06-security-and-i18n/01-security-and-data.md` §8 (which forbids blanket `unsafe-inline`). It MUST be allow-listed explicitly, never by relaxing the whole policy. Emit a per-request CSP nonce and attach it (`<script nonce="...">` with `script-src 'nonce-...'`), or allow the script by its `'sha256-...'` hash. The script content is static, so a hash is the simplest robust option.

> **Reduced Motion:** The toggle and any theme-transition animation must honour `prefers-reduced-motion: reduce` — see `02-frontend-and-styles/04-accessibility.md`.

## 4. The UI Toggle (WordPress Interactivity API)
The actual user-facing toggle button (e.g., in the header) avoids heavy JS event listeners. It utilizes the **WordPress Interactivity API** to seamlessly switch states, update `localStorage`, and manage accessibility properties (ARIA) without reloading the page.

```html
<button 
    data-wp-interactive="nexus-dark-mode"
    data-wp-on--click="actions.toggleTheme"
    data-wp-bind--aria-pressed="state.isDark"
    aria-label="Toggle Dark Mode">
    <!-- SVG Icon changing dynamically based on state -->
</button>
```
